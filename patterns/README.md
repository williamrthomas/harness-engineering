# Patterns

Doctrine names the laws. Patterns name the moves.

A pattern is a reusable shape — a way to spend tokens, structure tools, run
loops, hold memory, contain risk — that has been proven across many projects.
Each chapter here is short, concrete, and harness-agnostic. They apply to
Codex, Claude Code, Pi, and to whatever harness comes next.

| Chapter | The move |
| --- | --- |
| [01 — Context shaping](01-context-shaping.md) | Pick the smallest set of high-signal tokens. |
| [02 — Tool design](02-tool-design.md) | Few tools. Task-shaped. Self-explaining. |
| [03 — Sub-agents](03-sub-agents.md) | Delegate to protect context and isolate trust. |
| [04 — Memory and compaction](04-memory-and-compaction.md) | The agent forgets. The harness remembers. |
| [05 — Eval loops](05-eval-loops.md) | Three levels. Different cadences. Look at data. |
| [06 — CI as harness](06-ci-as-harness.md) | The pipeline is feedback for the agent. |
| [07 — Human in the loop](07-human-in-the-loop.md) | Approve at the right altitude. Never in the middle. |
| [08 — Security patterns](08-security-patterns.md) | Six patterns. Stack at least two. |

Patterns compose. Most production harnesses use four or five of them at once.
